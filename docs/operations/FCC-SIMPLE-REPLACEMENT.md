# FCC 简单全量替换：实施与隔离验收

> 历史评审记录：本文件中的逐阶段重新批准、后续缺失 FCC 活动不得停用、旧迁移路径等旧描述已被 [一次审批操作手册](FCC-ONE-APPROVAL-RUNBOOK.md) 取代。正式执行以前述手册与最终代码为准；此处保留供审计。

日期：2026-10-28。本文是评审与演练材料，**不是已执行的生产迁移**。用户已确认旧活动 ID 无需延续，也无需逐条审核或绑定历史活动。本方案取代此前文档中有关 32 条活动人工匹配、影子批次及绑定的上线前提；已有代码和文档保留，但本方案不调用它们。

## 结论与边界

使用已验证的 FCC 双遍完整采集，在单个数据库事务里把全部 FCC 活动写入独立私有表并切换读取源。旧 `public.furry_events` 的记录和 `(name,start_at)` 约束保持原样，用户在切换成功后只看到 FCC 活动。FCC 数据只以 FCC UUID 去重：合法的同名同日活动不会互相覆盖。新记录内部使用原活动 bigint 序列分配 ID，公开 API 返回十进制字符串；不承诺与旧活动 ID 对应。

这是一套本地隔离验证通过的候选方案，**不等于已具备立即上线条件**。正式实施必须重新核对生产权限、全部写入入口、备份恢复、线上调用方及 FCC 新快照，并单独获得生产变更授权。线上表、RPC、函数、工作流均未被本轮修改。

已取得的依据：生产只读元数据报告 32 条旧活动；此前核验为 8 条启用、24 条停用，可能变化。生产 `fetch-furry-events` v39 和 `furry-event-search` v25 为 ACTIVE 且 `verify_jwt=true`；实际线上客户端及所有外部写入者仍需核实。旧快照两遍均为 516 条、516 个 UUID，共 52 次 HTTP 200、无重试；状态为 scheduled 465、cancelled 35、rescheduled 11、postponed 5。这是当时的结果，不能保证今天或部署时总数仍为 516。

## 查询及展示约定

| FCC 状态 | 列表行为及文案 |
| --- | --- |
| `scheduled` | 保留并显示“已安排” |
| `cancelled` | 保留并显示“已取消”，不伪装为正常举办 |
| `postponed` | 保留并显示“已延期” |
| `rescheduled` | 保留并显示“已改期” |
| `movedOnline` | 保留并显示“线上举办” |
| 其他非空状态 | 保留原值，显示“状态待确认” |

默认搜索沿用上海时区的未来活动和未定日期筛选；指定年月或城市时按原接口筛选。因此**516 条入库不等于默认页面显示 516 条**。内部分页按真实 bigint 读取，公开查询在一个稳定数据库语句中组合页面，避免一次搜索混入切换前后的数据；最终按开始时间和 ID 排序。多个独立请求之间不保证数据永不变化。

数据库 RPC 本身不能证明调用方提供的数据来自 FCC 或完成两遍采集；这一证明依赖可信的 FCC Edge 采集器。只有可信的服务端持有对应高权限凭据，不能将该写入接口或 service_role 凭据交给公开客户端；生产中其他拥有 service_role、owner 或超级用户能力的主体须单独盘点和管控。

开放字段是名称、时间、地区、场地、主办方、状态、经允许的来源链接、受限图片及现有别名。公开投影不含 `raw_json`，并将未经安全渲染的 detail 原文设为 null；FCC 官方详情 URL 可用时，网页通过链接查看完整详情。图片仅允许 FCC 允许域名并经自有受限代理，失败用占位图。历史来源链接不再公开。Web 用文本节点显示名称和状态，不将活动内容解释为 HTML/Markdown；新的展示路径如需渲染富文本，必须另行实现白名单/转义并测试。**如果现有其他调用方依赖接口的 `detail` 原文，这一变化不兼容，须在切换前处理。**

FCC 官方允许字符串与 null 的字段，数据库和展示规则并非 FCC 契约：原始 detail 中的 U+0003 等保留在私有表；PostgreSQL 不支持 U+0000，因此导入前遇到 U+0000 直接中止，不截断或替换。其他字段的 trim/空字符串转换沿用现有适配器，不声称保留所有上游原始字节。此次 516 条样本中 516 条都有允许的详情及图片链接、开始时间均非空，2 条结束时间为 null；新采集必须重新验证。

## 已执行的隔离测试

1. 在临时本机 PostgreSQL 17 中，载入之前只读获取并标准化的 516 条 FCC 数据与 32 条旧活动的**有限字段投影**。投影不是完整生产备份。旧表的隔离测试数据在导入、重复同步和回滚前后保持一致；首次导入后读取 500 + 16 条，UUID 及 bigint ID 均唯一。该测试不连接生产。
2. 导入事务未提交时其他读取仍见旧源；提交后读到完整新源；手动中断事务后新表和源切换均回滚。失败场景覆盖重复 UUID、不完整标志、历史 FCC UUID 意外消失、不安全 URL、U+0000、上游第二页失败，均不发布部分结果。相同快照重复导入保持 FCC UUID 对应的 bigint ID 不变，两个合成同名同日活动不合并。旧来源回退后 FCC 行仍被保留。
3. 临时 Docker `--internal` 网络的 PostgreSQL 17 + PostgREST 13/JWT 端到端测试：anon/authenticated 不能直读旧表 `raw_json`、不能调用私有写入和读取 RPC；service_role 能调用完整导入与安全查询。SQL 角色与 HTTP/JWT 测试均为模拟权限，不能替代真实 Supabase 权限核验。
4. 已对 Web 默认分支源码副本应用现有补丁并运行 jsdom：两个同名同日不同 ID 的卡片均保留，FCC 链接可用，旧域名被屏蔽；已有测试覆盖图片占位、待定日期、恶意 HTML 文本。没有验证线上实际部署版本、浏览器真机或图片 CDN 的全量可访问性。

隔离 PostgreSQL 测试 `tests/db/fcc-simple-replace.test.ts`：10/10；隔离 PostgREST 测试 `tests/postgrest/fcc-simple-replace.test.ts`：1/1；应用测试 58/58，TypeScript 检查通过。以上不能推算生产请求耗时或容量。

## 生产实施前的阻断条件

- 确认线上 Web、Worker、其他客户端和三个旧 RPC 的真实调用路径，特别是原表直接读取及 detail 原文使用。任何尚需支持的调用方必须先有安全且经过验收的迁移方案。
- 只读复核生产完整 schema、主键/外键、RLS、表与列级 GRANT、角色继承、函数权限、sequence 所有权和当前调用方；排查旧 Edge、旧 RPC、定时/手动 Actions、缓存写入函数以及其他 service_role、owner 和外部写入入口。`service_role` 和数据库 owner 是可信高权限主体，超级用户/owner 可绕过普通限制；授权草案不能替代对这些主体的运行控制。
- 制作旧活动**全字段数据**、schema、RLS/GRANT、函数定义及序列状态的独立备份，在隔离环境恢复并核对数量、字段及可用性；此前的历史投影不是完整备份。确定备份保管和恢复负责人。
- 在实施前重新进行受控 FCC 双遍只读采集，确认每遍总量、UUID 集合和规范化内容一致、无重复或缺页、无 U+0000；若总量已改变，记录变化并让操作人依据最新数据决定是否继续。观察认证/限流和响应体大小；此前 516 条的结果不应冒充当前结果。
- 用目标 Supabase 版本和权限配置核对审阅后的正式迁移、PostgREST 单请求体/响应体、函数/数据库超时及 Web 字段行为。确认 516 条实际大小可在目标资源限制内一次处理；合成环境耗时不是生产保证。
- 明确维护窗口和负责人，审核备份、旧任务排空、部署顺序、验证、停止及回滚；取得用户对具体生产变更的再次明确授权。

## 经批准后的最短操作顺序（本轮不执行）

1. **窗口前，只读准备。** 保存并验证独立备份；核实旧表 32 条实际数量及全字段校验基线、真实序列状态、实际写入者和调用者；完成 FCC 新快照与 Web/权限预演。检查并确认本次应上线的 commit、正式迁移文件和函数包；不要运行此前的历史绑定或影子批次 SQL。
2. **进入维护窗口，冻结并排空。** 实际禁用远程 main 的旧定时和手动触发入口；禁止所有已识别的其他旧写入入口启动新任务；等待排队和在途工作流、函数和数据库事务结束并检查活动事务/日志。单靠 Actions 开关不算排空。冻结后制作并验证最终全字段备份和基线，确保包含冻结前最后一次写入。必要时短暂停止相关用户查询，避免部署期间读到不兼容接口。
3. **部署权限与读取路径。** 按批准的迁移文件创建私有表及 RPC，撤销 anon/authenticated 的旧表表级和列级权限、撤销旧 service_role 写入权限与旧同步 RPC 执行权；保留受控服务读取。校验非 owner 旧写入者确实被拒绝。先部署新 `furry-event-search` 和图片函数，部署经审核的 Web 补丁，验证此时旧源通过安全投影可读。旧表暂时保留，旧链接及 detail 原文不直接暴露。如有未知写入者或客户端失败，停止并回退，不进入导入。
4. **一次性完整导入并切换。** 部署经批准的 FCC `fetch-furry-events` 版本与已安全配置的 Token，手动触发一次。它进行两次独立完整分页、比较内容并预检，再调用一次数据库 RPC；数据库在一个事务中按 UUID upsert 所有行并将来源切到 `fcc`。空快照、分页错误、漂移、认证/网络/限流、U+0000、重复 UUID 等直接停止，不自动重试。若请求超时且提交状态不明，先查询来源与结果核对，禁止盲目重试。新采集若和已批准基线明显不一致，停止并复核。
5. **切换验收。** 按服务端权限核对 FCC 总数、唯一 UUID 数、状态分布和零重复；同次快照数量与官方一致。确认旧表的全字段基线未变、未删除；测试真实 Web 的默认查询、城市、年月、500 条边界、卡片、图片、详情链接及四种状态，确认公开 API 无 `raw_json`/原始 detail；anon/authenticated 直接读原表和私有表应失败。默认页面只显示筛选后的活动，不能用其条数冒充完整库存。
6. **退出窗口及后续同步。** 所有验证通过后恢复公开访问并监控；仅在新的定时工作流和写入入口完成审核、冻结策略验证并获授权后才恢复定时同步。此草案对后续上游 UUID 缺失采取失败关闭，不自动停用活动，需先核实缺失及操作方式；这是 FCC 后续数据变化处理，并非旧活动人工匹配。

以上步骤 2–5 需要维护窗口；步骤 1 可提前进行。具体窗口时长须根据目标环境彩排，不应根据本地测试时间承诺。

经授权并应用最终迁移后，维护人员可用受限管理连接执行以下**只读**核验；它们读取草案中的对象，不输出活动原文或凭据。预期值取自切换时刚完成的 FCC 双遍采集，不固定假设永远是 516：

```sql
select source from furry_fcc_simple_private.settings where singleton;
select count(*) as total, count(distinct fcc_id) as unique_fcc_ids
from furry_fcc_simple_private.events where is_active;
select native_status, count(*) as total
from furry_fcc_simple_private.events where is_active group by native_status order by native_status;
select count(*) as legacy_rows from public.furry_events;
```

第一行应为 `fcc`，总数与唯一数都应等于最新完整采集数；状态总和应相等；旧表计数及其全字段内容与冻结后备份一致。还必须用实际 anon、authenticated JWT 和 Web 验证公开路径，不能仅凭管理员连接的结果宣称权限正确。

## 回滚与恢复

出现异常时先阻止新的 FCC 和旧同步，排空在途写入，确认事务提交状态；不要删除任一数据表，不要降低序列值。经单独批准，维护连接可以将 `furry_fcc_simple_private.settings` 中唯一行的 `source` 改回 `legacy`；这一切换不删除 FCC 数据，旧表仍为原有记录。旧活动将通过安全投影显示，退役链接不可用、详情原文不公开，不等同恢复以前的所有外部资源。验证旧表和安全查询后再决定是否恢复访问。不要自动恢复旧同步函数、原表公开权限或旧 Actions；如果还要恢复过去的写入链，需要单独审核、恢复相应权限并授权。备份及其隔离恢复用于处理比单纯回切更严重的损坏。

仅在以上冻结和排空完成、明确批准回切后，使用具有维护权限的连接执行以下回切语句，确认 `returning` 返回一行 `legacy`，随后重新运行安全查询和旧表核验：

```sql
begin;
set local lock_timeout = '5s';
update furry_fcc_simple_private.settings set source = 'legacy'
where singleton returning source;
commit;
```

任何一步遇到权限意外、未知写入、备份不能恢复、数据差异、契约错误、未确认的客户端故障或超时结果不明都应停止。方案完成和隔离测试成功均不构成生产变更授权。
