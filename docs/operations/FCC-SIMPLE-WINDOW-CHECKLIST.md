仅为评审草案；本轮不得在生产执行。使用前须确认生产部署授权、责任人及窗口。负责人以下为**待指派的角色**，不表示已有具体人员接受任务。完整步骤及 SQL 草案参见 [简化替换方案](FCC-SIMPLE-REPLACEMENT.md) 和 `sql/review/fcc_simple_replace.sql`。旧 32 条活动无需逐条匹配，且不删除。

最新只读检查：旧表 32 条（8 启用）；anon/authenticated 能读取包括 raw_json 在内的列；旧同步仍可按名称和日期写入。远程 main 的旧定时任务支持手动触发并带重试。线上 Worker 当前运行旧版本且包含旧源访问，路由与流量仍待核实。三个旧查询 RPC 的实际外部调用尚未查明，Flutter 历史安装版本及其缓存写入函数是否在线上运行也待确认。

2026-10-28 12:22 UTC 完成 FCC 新的双遍只读采集：52 次 HTTP 200、零重试，每遍 516 条及 516 个唯一 UUID，规范化内容一致、无 U+0000；RPC 请求体估算 611,595 字节，单页响应最大 36,353 字节。这是该时点结果，窗口前须核对时效。已在本地私有目录取得只读逻辑导出，含旧表 32 条全部 39 列及有关数据库元数据；它不是 pg_dump/PITR，未冻结的实时状态可能变化，不能代替步骤 2 的最终备份和恢复核验。

将该导出的全字段数据恢复到临时隔离 PostgreSQL 的生产形状模拟表，再在同一集群的另一个数据库中进行 pg_dump/pg_restore：全列摘要、RLS、策略数、角色表权限和序列状态一致。角色预先存在，模拟表不是全量生产集群；未验证跨集群角色恢复和生产 PITR。使用最新快照的隔离导入与中断/回滚测试 10/10、PostgREST/JWT 1/1 通过；本地两次 SQL 函数测得约 36–39 毫秒、包括容器和 psql 的墙钟约 145–180 毫秒，不能推算生产耗时。

Cloudflare Pages 生产部署元数据与对应源码确认现行 Web 仍按名称/日期/城市去重；本地补丁及测试增加按 ID 去重和屏蔽旧 Worker 缓存链接，但尚未发布。Worker 的 workers.dev 子域已启用，其实际流量、service binding、外部调用和历史安装包需要核实。

本地空快照误报已修复并加入测试，但生产尚未部署。采集 90 秒、客户端 120 秒并不等于生产数据库和 Edge 超时预算已确认：SQL 草案中的 `SET LOCAL statement_timeout` 只对草案事务有效，不能自动限制后续同步 RPC；发生超时必须核对实际提交状态。不要使用包含旧迁移的 `supabase db push` 代替本方案的已审阅正式迁移。
